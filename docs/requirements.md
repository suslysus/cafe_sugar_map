# 기능 명세

기준일: 2026-10-17. 팀원이 제공한 확정사항을 정리한 문서이며, 아래 ‘수용 기준’은 구현 후 확인할 기준이다. 구현 완료를 뜻하지 않는다.

## 확정 기능

| ID | 기능 | 구현 후 수용 기준 | 담당 |
| --- | --- | --- | --- |

## 범위 구분

- 확정: 네 페이지, 브랜드 4곳, 최소 사이즈의 가격·당류·칼로리, 로그인 기반 즐겨찾기, 조건별 랜덤 추천.
- 2페이지에 배치할 예정인 진입 동작: 검색 결과에서 ‘비교에 추가’.
- 시간 여유 시 구현: 별도 비교함·장바구니 및 비교 화면.
- 추후 추가: 길 안내.
- 미정: 비교 목록의 표시·보관 방식, 카테고리 중복 처리, 브랜드 선택 개수, 지도 API와 인증 방식. 비교에는 옵션을 추가하거나 변경하지 않는다.

## 예외 처리 제안 — 팀 확인 필요

아래는 확정 기능을 안정적으로 구현하기 위한 설계 제안이다.

- 위치 권한 거절·오류: 숭실대 기본 위치와 현재 상태를 함께 안내한다.
- 검색 결과 없음: 빈 결과 안내와 조건 초기화를 제공한다.
- 추천 후보 없음: 선택 조건에 맞는 음료가 없다고 안내하고 조건을 바꾸게 한다.
- 다른 사용자 로그인: 각 계정의 즐겨찾기 목록을 분리한다.
- 정보 미확인: ‘정보 확인 중’으로 표시하며, 누락된 영양성분을 0으로 간주하지 않는다.
- 로그인 후 즐겨찾기: 로그인 성공 후 원래 메뉴로 돌아가는 흐름을 검토한다.

## 확인 시나리오

| 시나리오 | 예상 결과 |
| --- | --- |
| 처음 접속 후 위치 허용 | 현재 위치를 기준으로 지도가 열린다. |
| 위치 거절 또는 취득 실패 | 숭실대 기준 지도가 열린다. |
| 지도에서 대상 카페 선택 | 오른쪽 메뉴 목록이 해당 카페로 바뀐다. |
| 메뉴 선택 | 가장 작은 사이즈의 상세 정보와 기본 레시피·옵션 추가 및 변경 없음 기준이 보인다. |
| 브랜드·카테고리 검색 | 선택 조건에 맞는 결과만 보인다. 세부 분류 규칙은 별도 확정한다. |
| 비로그인 상태에서 즐겨찾기 | 로그인 안내가 나온다. |
| 로그인 후 목록 열기 | 해당 사용자의 저장 메뉴가 보인다. |
| 브랜드·카테고리로 추천 | 조건에 맞는 후보 중 하나만 반환한다. |

현재는 설계 검토용 시나리오이며, 실행 결과는 아직 없다.
