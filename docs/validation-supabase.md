# Supabase 로그인·마이페이지 검증

검증일: 2026-11-03. 화면 검증 담당: Luna low. 실제 DB와 브라우저 모의 검증의 범위를 구분한다.

## 실제 Supabase 프로젝트

- Project URL의 Auth 설정 조회 HTTP 200. Email 로그인·회원가입 활성화, 이메일 인증 유지 확인.
- profiles/favorites 생성, RLS 활성화, 각각 정책 2개/3개, anon SELECT 권한 없음 확인.
- `supabase/tests/rls.sql` 실제 실행 통과: 본인 프로필 조회·이름 수정, 본인 즐겨찾기 저장·삭제, 타인 행 조회·수정·삭제·대리 저장 차단, 프로필 소유자 컬럼 변경 차단, anon 조회 차단.
- SQL 테스트의 임시 사용자·프로필 모두 ROLLBACK되었음을 결과에서 확인.
- 실제 공개 키로 비로그인 profiles/favorites 조회가 HTTP 401 / Postgres 42501로 거부됨을 확인.
- Site URL localhost:8000 및 두 로컬 mypage Redirect URL 등록 확인.

## 격리된 브라우저 검증

Playwright + Edge headless, Supabase SDK fixture, 데스크톱·모바일 검사 **81개 통과**, 콘솔·페이지 오류 0건. 테스트 중 외부 요청은 0건이며 실제 사용자·비밀번호·메일을 사용하지 않았다.

주요 검사: 로그인·가입·인증 대기·메일 재발송 안내·요청 제한, 비밀번호 복구 화면과 비밀번호 확인, 프로필 이름 편집·XSS 문자열 텍스트 처리, 즐겨찾기 저장·삭제·새로고침·계정 격리·지연 응답, 목록 오류 후 재시도와 배너 해제, 외부 returnTo 차단, 잘못된 키/URL·설정 누락·SDK 누락 시 차단, 복구 중 계정 전환, 네 페이지 이동과 모바일 가로 넘침.

공식 SDK를 대체하지 않은 별도 smoke 검사에서도 빈 브라우저 컨텍스트의 실제 번들 로드·Auth 초기화·로그인 폼 활성화·사용자 null 상태를 확인했다. 콘솔 오류와 외부 요청은 없었다. 이 검사는 실제 로그인을 시도하지 않는다.

## 별도 실제 계정 확인

본인 이메일로 회원가입 → 인증 메일 확인 → 로그인 → 메뉴 즐겨찾기 저장 → 마이페이지 조회 → 새로고침·다시 로그인으로 유지 확인을 직접 진행한다. 비밀번호 재설정 메일 수신과 본인의 새 비밀번호 입력·변경도 직접 확인한다. 위 81개 모의 검증이 실제 이메일 전달·Auth 계정 생성 성공을 증명하지는 않는다.

관련 실행·설정은 [Supabase 안내](supabase-setup.md), 원격 DB 검사 재현 소스는 `supabase/tests/rls.sql`을 참고한다.
